# Manual task inbox

Open **Task inbox** with `Shift+B` (rebindable under Settings → Hotkeys), or from a project's right-click menu. The inbox is stored by the daemon in the same SQLite database as projects and sessions. It survives closing the TUI and restarting the daemon.

- `Ctrl+A` or **New** captures task text. `Enter` saves the capture; `Shift+Enter` / `Ctrl+J` inserts a newline. Capture does not launch an agent. While saving, the source editor is frozen until confirmation; a failed save keeps the text editable for retry.
- Select a task and press `Enter` or **Review** to open the existing Quick Prompt. The immutable **Original** stays in the inbox; the box edits a separate set of approved instructions. Initially the box contains a copy of the original text.
- Use the Quick Prompt's project (`Ctrl+P`), existing worktree (`Ctrl+T`), harness (`Tab`), model (`Ctrl+O`) and preset (`Shift+Tab`) pickers. Picking a preset never auto-launches an inbox item, including presets configured to skip their task box.
- `Ctrl+S` or **save review** saves the composed instructions and launch choices without launching. `Enter` explicitly approves and launches through the ordinary agent creation path. Empty input, `Esc`, an outside click and the force-close key do not launch. Unsaved review edits are discarded on cancellation; the previous saved review and original remain durable.
- `Ctrl+E` or **Details** opens **Done when**, **Constraints**, **Verification plan**, and **Review note / results**. These fields start empty even for imported issues. `Tab` / `Shift+Tab` or clicking a field selects its multiline editor; `Enter` inserts a newline. `Ctrl+S` / **Save details** persists a review revision without launching. `Esc` / **Close** discards unsaved edits; an already submitted save may complete. Pending saves freeze input; a failed save retains the edited text for retry.
- In **Details**, `Ctrl+O` cycles **Needs review**, **Accepted**, **Needs changes/rework**, and **Abandoned**; clicking an outcome selects it. Save explicitly to record the decision. These are user outcomes, separate from the session status and from archive. Use the existing linked session for rework; changing an outcome never creates another run.
- `Ctrl+O` or **Session** revisits the linked session. An item can launch once; repeated requests return that same session. Deleting the session leaves the link as a tombstone, preventing an accidental relaunch.
- `Ctrl+D` or **Archive/restore** dismisses or restores an item. `Ctrl+L` or **Archived** switches lists, and `Ctrl+R` refreshes changes from other clients. Typing filters the list; the first `Esc` clears the filter and the second closes it. A click selects a row; the **Review** button opens it.

In the existing GitHub Issues modal, `Ctrl+B` captures the selected issue's title, body and URL. It uses the already retrieved issue data and performs no GitHub write. Review and launch then use the same Quick Prompt as a manual capture. The issue URL remains ordinary persisted issue context on the created session.

## Persistence and launch guarantees

Migration 30 adds `inbox`, with immutable source text/URL, a separately serialized `InboxDraft`, archive state, timestamps and a session link. Tasks do not depend on a project's or session's lifetime. Worktree selection identifies the owning project. Saved model/effort choices, including an explicit CLI default (no flag), survive later settings changes. Original source text is limited to 64 KiB and approved instructions to the existing 16 KiB starting-prompt limit; launch options are bounded too. Criteria, constraints, verification plan and review note together are limited to 16 KiB. The composed launch prompt, including criteria, still obeys the existing 16 KiB first-prompt limit. Saving instructions or criteria checks their combined budget when an unlaunched task already has a draft; an oversized save fails and keeps the previous durable revision plus the edited form for correction. A task without approved instructions checks that budget when instructions are saved or launched. List replies contain one bounded task per frame.

IPC v54 extends the binary inbox records and launch draft with reviewed details and their revision. Because this changes existing frame shapes, both protocol version and compatibility floor are v54; older clients/daemons must reload together. The TUI also gates inbox requests on older connections. Inbox events are never sent to unrelated subscribers. Inbox bodies are omitted from server-event debug logging.

Review, archive and launch serialize through a daemon operation gate. An explicit launch first saves the approved draft, then uses the normal `CreateAgentSpec` validation/spawn path. The agent uses the inbox item's stable ID, and agent insertion plus the inbox link commit in one SQLite transaction before a PTY starts. Publication, initial PTY installation and known-failure rollback hold the same spawn gate as Attach and background prewarm, so neither can resume a second PTY in that interval. A known spawn failure rolls back the agent/link and keeps the approved draft. Concurrent requests, a lost acknowledgement and retries after daemon restart cannot create a second session. Agent status updates never archive or resolve the inbox item.

As with ordinary Quick Prompt launches, the first prompt is passed once, not replayed on every resume. A process crash between committing the link and spawning/delivering the prompt is an ambiguous delivery: the item stays linked to its one agent row. Retrying the inbox launch does not create another row or replay the prompt; ordinary Attach/prewarm can still resume or start a PTY for that linked row. Inspect that session and use an explicit follow-up if needed. This milestone does not promise exactly-once prompt delivery across OS process crashes.

## Criteria, decisions and audit

Migration 31 adds reviewed details, a revision counter, an independent launch snapshot and `inbox_review_history`. Existing records upgrade to empty criteria, constraints, verification plan and note, with **Needs review**. Legacy approved instructions remain intact. Every explicit details save appends a complete snapshot with an event ID, revision and timestamp. The TUI shows the latest 20 snapshots in the existing task reading pane (PageUp/PageDown or mouse wheel); the complete audit remains in SQLite. Conflicting concurrent edits fail rather than silently overwriting a newer review. An unchanged retry uses the same event ID and cannot create a duplicate decision or revert a later one. On a conflict, copy any edits you want to keep, close, refresh, then reconcile with the latest revision.

The launch review identifies the saved criteria revision. The daemon rejects stale approvals before launching, and composes approved instructions plus clearly labelled **Done when**, **Constraints** and **Verification plan** sections exactly once. Original source and review-result notes are never added to those sections. A verification plan is descriptive, user-reviewed text; Nebula does not execute it, parse commands from imported source, ingest test results or ask a model to decide acceptance.

The session link transaction records the launch criteria revision, prompt and known harness/model/effort selections. A missing model or effort means no explicit flag; it does not claim to know the provider's effective default or later changes inside the agent. These records are not billing or performance metrics. Existing launches from before migration 31 have no backfilled snapshot. Criteria revised after launch remain in the audit and do not change the prompt already delivered to that session.

Accepting or abandoning a task requires an explicit saved user decision. Agent termination, a finished turn, passing tests and model opinions never change the outcome. Archiving does not accept or abandon it. Review notes describe the user's observed results; inspect files, diffs and tests through the existing session/review surfaces, then record a decision here. No new diff viewer or automatic verification runner is added.

## Scope and extension boundary

This milestone selects existing worktrees. Create a worktree in Nebula first, then select it in review; inbox review does not create a checkout or offer Claude Cloud mode. Linked sessions that have been independently archived should be restored with Nebula's existing session controls.

Classification, automatic suggestions, automatic evaluation ingestion, billing estimates, learned routing and provider-specific routing are deferred. Manual review audit records are implemented; they are not model evaluations. Future optional records should reference `InboxId` in their own tables/modules and become instructions only through explicit review. They must not overwrite original content, silently change an approved draft or trigger launch. No model packages or classifier are required here.

The fork's existing harness permission defaults are unchanged. Review those defaults before trying real agents. Cloud tests use stub agents and disposable repositories; they do not establish GPU performance, desktop terminal behavior or Omarchy compatibility.
